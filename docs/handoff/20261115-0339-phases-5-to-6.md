## Facts that cost time this session (also in `docs/gotchas.md`)

- Every build id carries a timestamp, so **every `autotest.py run` restarts the instance (~15 s)**; batch the named scenarios.
- A step that waits for "the view shows X" is vacuous if X equals the old state: `Shows()` also demands
  `BarAdapter.AppliedVersion == ViewState.Version`.
- Messages (a colonist's death, "Critical alert: Major break risk") are `ImmediateWindow`s that swallow real clicks: clear
  them before real input and keep fixture moods ≥ 0.5.
- Real clicks occasionally never reach `Window.ExtraOnGUI` (unexplained; `InputProbe` shows the raw events): `FocusSearch`
  retries and logs the attempts.
- A `NameSingle` pawn alive while another pawn is generated throws in vanilla (`PawnRelationWorker_Parent`): fixtures
  use a triple and switch to a single only after generation.
- Run the scenarios that save/load (`View reset on load`) **before** the real-input ones in a batch: a load exposed a
  regression (the bar's recache throws while the new game has no world) that only showed in what ran after it.
