## Verified engine facts (decompiled 1.6.4871 unless marked)

**Predicates**

- **Injured (Q3):** `pawn.health.hediffSet.HasNaturallyHealingInjury()`: any `Hediff_Injury` with `CanHealNaturally()`.
- **Idle (Q4) is the last branch of a precedence chain** in `ColonistBarColonistDrawer.DrawIcons`. The idle icon shows only
  when none of these apply, in this order: dead (no icons at all) → `InAggroMentalState` / `InMentalState` →
  `InBed() && CurrentBed().Medical` → asleep (`CurJob != null && jobs.curDriver.asleep`, or in a caravan and
  `needs.rest.Resting`) → `CurJob.def == FleeAndCower` → attacking (`AttackMelee`/`AttackStatic`, or `Wait_Combat` with a
  valid `stance_Busy.focusTarg`). Then: **`colonist.mindState.IsIdle && GenDate.DaysPassed >= 1`.**
  `IsIdle` = `!Downed && Spawned && lastJobTag == JobTag.Idle`.
  **The TODO's one-line summary of Q4 says "not drafted" as if literal: it is not a term in the chain.** Drafted pawns are
  excluded, if at all, through `lastJobTag`. The user's decision is "exactly the bar's idle-icon condition", so implement
  the chain as written and prove in a scenario that a drafted colonist is not idle; do not add a clause the bar lacks.
- `GenDate.DaysPassed` = days of **`TickManager.TicksGame`** (ticks since the game started). **A fresh quicktest map is at
  day 0, so Idle is false for every colonist for the first 60000 ticks.** Tests must advance it:
  `Find.TickManager.DebugSetTicksGame(n)` exists (used by vanilla's own storyteller/raid code).
- Drafted: `pawn.Drafted`; setter `pawn.drafter.Drafted = true` is public.
- Skills: `pawn.skills?.GetSkill(SkillDef)` → `SkillRecord` (`.Level`, `.TotallyDisabled`, `.PermanentlyDisabled`).
  `Pawn_SkillTracker.skills` is a public list. Skills are null for non-skilled pawns (guard).
- Mood: the bar itself uses `pawn.needs?.mood?.CurLevelPercentage` (`Need.CurLevelPercentage` has a setter; sibling mod
  Colony Web's fixtures set it).
- Names: `Name` is `NameTriple` (`First`, `Nick`, `Last`) or `NameSingle`; both derive from `Name` (`ToStringFull`,
  `ToStringShort`). The bar draws `pawn.LabelShortCap`, **truncated to the portrait width** (`GenMapUI.GetPawnLabel`):
  match and sort on the untruncated name. FR-01 wants the displayed name plus constituent parts.
- `pawn == null` entries are the bar's placeholder for a map with no colonists. Dead colonists are entries too (`pawn !=
  null`, corpse on map or carried); `Pawn.Dead`, `needs` may be null.

**Seam facts that shape the real view (from Phase 1; details in plan §1.2/§1.5)**

- `ColonistBar.Entry` is a `struct` (`pawn`, `map`, `group`, `reorderAction`, `extraDraggedItemOnGUI`): assign fields on a
  local copy. Group ids **must be contiguous from 0** (the layout indexes per-group arrays by group id); groups that lose
  every entry must vanish and the rest be renumbered. Vanilla's draw loop indexes `Entries[i]` for every
  `DrawLocs[i]` and `cachedReorderableGroups[i]`: never leave `DrawLocs.Count > Entries.Count`.
- Re-application is cheap and flag-free: "does every entry still carry our shared `reorderAction`?" Phase 2 needs a second
  trigger too: **a criteria version** (a changed query/filter/sort must force a rebuild even though the list still
  looks like ours). Switching the view on already starts from a fresh vanilla cache (`MarkColonistsDirty()`, then read
  `Entries`); keep that for criteria changes so vanilla's reorder groups reset.
- With nothing active the bar must be **untouched**: switching off only calls `MarkColonistsDirty()`.
- The first draw after switching off draws with the bar dirty: that is vanilla restoring itself, not a flash.
- `ColonistBar.Visible` is false below 800×500 (`UI.screenWidth/Height`, scaled units): **the controls must hide too.**

**Widgets (Phase 3/4)**

- `QuickSearchWidget` (`RimWorld`): `OnGUI(Rect rect, Action onFilterChange = null, Action onClear = null)`; public
  `filter` (`Text`, `Active`, `Matches(string)`: **trims and matches case-insensitively as a substring**, so FR-01's
  whitespace and case rules come with it; a whitespace-only query is `Active` but matches everything), `Focus()`,
  `Unfocus()`, `CurrentlyFocused()`, `Reset()`, `maxSearchTextLength` (30), `noResultsMatched` (turns the text red),
  `WidgetHeight` 24. It handles Esc **only while focused** (unfocus + `Event.Use()`, so the main menu does not open),
  unfocuses on a mouse-down outside its rect, and draws its own × that clears the text. **It draws no placeholder**; the
  spec's "Search colonist by name" placeholder must be drawn by us when empty and unfocused.
- `Window.CommonSearchWidget` (override returns the widget) makes the **base window draw it automatically** in
  `InnerWindowOnGUI` at `QuickSearchWidgetRect(winRect, inRect)` (protected virtual; by default the window's bottom edge)
  and resets it in `PreOpen`. Do **not** also draw it yourself. And do not skip the override: `WindowStack.AnySearchWidgetFocused`
  is what suppresses game hotkeys while typing (from plan §1.3; **[verify]** in game with real keystrokes).
- `FloatMenu`: `Find.WindowStack.Add(new FloatMenu(List<FloatMenuOption>))` (pattern used by Colony Web's debug picker).
  `DefDatabase<SkillDef>.AllDefsListForReading`; label `SkillDef.skillLabel`.
- Layout numbers: bar width `UI.screenWidth − 520` (260 px free per side), top margin 21, portrait `48 × scale`, row pitch
  `(48 + 32) × scale`, group frame expands `12 × scale`, a weapon icon may hang at `y + 1.05 × height` when the preference
  is on. At 800 px: 3 portraits fit at scale 1, 5 shrink to ~0.77. What vanilla draws in the free side areas at the top
  and where the alerts sit are **unverified**: check by screenshot (`tools/screenshot.sh`) before placing controls.

## Phase 2: roster snapshot and predicates

Goal (`TODO.md` Phase 2): `ViewState` and `Predicates`; pure `RosterView` (filter pipeline, per-group stable sort with ties
to the vanilla index, chip counts); `BarAdapter` uses it (identity view when nothing is active); fixtures; scenarios
`Name search`, `Status chips`, `Combined filter`, `Sort and restore`, `Bar integrity`.

1. **`ViewState`**: static, memory only (query, status, skill, min level, sort key, direction) plus a version counter.
   Hard constraint (AGENTS.md): it **resets on load**. A static survives a load (the Bootstrap object does), so something
   must notice a new game (compare `Current.Game` to the one it last saw). **Open point 6.**
2. **`Predicates`**: name (First/Nick/Last/`LabelShort`, trim, `OrdinalIgnoreCase` substring, or reuse
   `QuickSearchFilter.Matches`), drafted, injured, idle (the whole chain above), skill ≥ N (unavailable when `skills ==
   null` or `TotallyDisabled`: excluded from the filter, sorted last), mood (`null` → sorted last whatever the direction).
3. **`RosterView`**: pure (`RosterView` must not touch `GUI`, `Widgets`, `Find`); `(vanilla entries, ViewState) →
   filtered + sorted entries, chip counts`. Sort **per group** (map/caravan), tie → vanilla index, then
   `thingIDNumber`. Chip counts: eligible, name-matching pawns satisfying each chip **ignoring the active status and
   skill** (spec §3.2). Placeholder (`pawn == null`) entries: plan says keep only when no filter is active; drop them
   when a filter is. Check a sort-only view.
4. **`BarAdapter`**: replace the probe rule with `RosterView`; keep `Disable`, the contiguous-group renumbering, the
   no-op `reorderAction` / `extraDraggedItemOnGUI`, `IsView`, and add the version trigger. Identity view (nothing active,
   sort = Vanilla) must leave the bar completely vanilla, including drag reorder.
5. **Fixtures** (colonists only): names, drafted, an injury hediff, skill levels, a mood offset. All **unverified
   suggestions**: injury as a hediff (`HediffMaker.MakeHediff` + `health.AddHediff`; the playbook says never `TakeDamage`
   for fixtures), skills via `GetSkill(def).Level = n`, draft via `drafter.Drafted`, idle via
   `mindState.lastJobTag = JobTag.Idle` (a public field) **plus** `DebugSetTicksGame` past day 1. Mood set directly may
   be overwritten at the next need interval; if so use a memory thought or pause. Pause time
   (`Find.TickManager.CurTimeSpeed = TimeSpeed.Paused`) once staged so state cannot drift while asserting (playbook:
   "latched flags and thresholds beat instantaneous values").
6. **Scenarios**, each with a stated precondition, trigger, failure mode and assertions on its own fixture colonists:

   | Scenario | Failure mode |
   | --- | --- |
   | `Name search` | wrong match on case, partial, first/last, whitespace; no-match leaves a broken bar |
   | `Status chips` | wrong predicate or count for Drafted/Injured/Idle; more than one status active; Idle disagrees with the bar's own icon |
   | `Combined filter` | AND broken; `All` drops the search |
   | `Sort and restore` | non-deterministic ties; vanilla order not restored; **`displayOrder` mutated** |
   | `Bar integrity` | draw locations out of step with entries after a dirty, hit test returns a hidden pawn, a drag writes `displayOrder` (reuse `BarProbe` and the Phase 1 helpers) |

## Phase 3: search field and filter strip UI

Goal (`TODO.md` Phase 3): `QuickSearchWidget` right of the bar; chips under the bar's lowest row with counts; empty state
with reset; keyed translations; responsive collapse; never overlap portraits or alerts.

- Put the controls in `ColonyCommandWindow`. Its rect is computed **once per frame** from the bar's `DrawLocs` / `Size`
  (in `WindowUpdate` / `LateUpdate`, not mid-event: IMGUI needs the same layout in the Layout and Repaint events of a
  frame; this is reasoned, not yet measured), shrunk to the controls only so it never covers a portrait or steals its
  clicks. Chip strip below the lowest portrait row *plus* the label space (`32 × scale`) and any group frame.
- Search: override `CommonSearchWidget` and `QuickSearchWidgetRect` (see "Widgets"); draw the placeholder ourselves; **Enter
  selects the first visible result with normal selection semantics**. Verified in `Selector.SelectUnderMouse` (private):
  a click on a **caravan member's** portrait does `CameraJumper.TryJumpAndSelect(caravan)`; any other portrait resolves
  through `ColonistBar.ColonistOrCorpseAt` (the corpse for a dead colonist) and then `ClearSelection(); Select(thing)`
  (Shift toggles instead). The world view goes through `WorldSelector`. Mirror that, do not invent a new path. A hidden
  selected pawn stays selected: never touch the selection except for that Enter.
- Chips: All / Drafted / Injured / Idle, counts, one active, click again toggles off, `All` clears status and skill.
- Empty state: "No matching colonists" in the controls (FR-04), reset reachable, no broken portrait region.
- Strings: `Languages/English/Keyed/ColonyCommand.xml`, keys `ColonyCommand_*`, `"ColonyCommand_X".Translate()`
  (`package.sh` already copies `Languages/`). Whether `rwdefs.py lint` checks Keyed files is unverified.
- Responsive: collapse the search to an icon and the chips into a Filters menu when space is short; below 800×500 draw
  nothing (the bar is hidden). The display-size × UI-scale matrix is **user-in-the-loop** (Phase 6); do not try to
  automate it.
- Automatable with the Phase 1 machinery (real input via `Xdo`, which refuses any display but the harness's Xvfb): typing
  into the field narrows the bar; a hotkey letter typed in the field does not trigger the game action; Esc unfocuses; ×
  clears the query only; Enter selects the first result. Pick scenarios by failure mode and keep to the strict scope.

## Process reminders and gotchas learned

- Run the harness as `source tools/env.sh && tools/autotest.py run "<exact scenario names>"` (the new instance needs ~15–20 s
  to restart per build; a run is ~20–60 s). It runs beside the user's game by design; it only ever kills processes
  carrying this repo's private `-savedatafolder`. `tools/autotest.py stop` at the end of a session. Check
  `pgrep -x RimWorldLinux`: the user's pid must still be there.
- A bare `sleep N` is blocked in this environment: use background commands and `Monitor` with an `until` loop.
- **Step labels and log text must not contain error-like words** (`error`, `Exception`, `Failed`, `Missing`, `not
  found`...): the harness classifies log lines by words and fails a run whose verdicts are all PASS. A scenario that
  provokes the mod's own `[ColonyCommand] ERROR` must swallow it (`ErrorCapture`).
- A scenario passes vacuously unless it has a **control** (Phase 1: the flash detector with the hooks removed, the drag
  that must reach `ColonistBar.Reorder` on the vanilla bar). Do the same where an assertion could pass trivially.
- Never call `ColonistBar.Entries` in a scenario's `Update` step to *observe* the view while it is on: the getter recaches
  when dirty and hides what the bar would have drawn. Read the private fields through `BarProbe`, as the Phase 1
  scenarios do.
- Dirty-tree builds are `-dirty` and restart the instance on every run; commit before measuring where it matters, and
  record the build id honestly in `docs/test-runs.md`.
- The harness window is **800×500** because the bar is invisible below that.
- Commits: small, imperative, `P2:`-style prefix, `git -c safe.directory="$PWD" ...`; never commit `.devlog/`, `.tools/`,
  `dist/` or build output. A TODO box is ticked only after a run proved it, naming the run, with a row in
  `docs/test-runs.md` listing the scenarios and the failure mode each covers.
